# 数据库设计

> 依据：v2.0 第五章。存储：PostgreSQL；迁移：Alembic。

## 1. 数据模型总览

```
Project 1 ──── N Trace 1 ──── N Span
                   │ 1
                   │ N
                TokenUsage
Project 1 ──── N DiagnosticTask 1 ──── N DiagnosticFinding
Project 1 ──── N MemoryRecord
(独立) KnowledgeDocument 1 ──── N Chunk（存 Qdrant，保留 document_id）
```

## 2. 表结构

### 2.1 Project（项目）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | 主键 |
| name | String | 项目名 |
| api_key_hash | String | SDK 鉴权 key 的哈希（不存明文） |
| created_at | DateTime | 创建时间 |

### 2.2 Trace（一次 Agent 任务执行）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | 主键 |
| trace_id | String UNIQUE | Trace 唯一标识 |
| project_id | UUID FK | 所属项目 |
| name | String | 任务名称 |
| status | String | 执行状态 |
| started_at | DateTime | 开始时间 |
| ended_at | DateTime | 结束时间 |
| duration_ms | BigInt | 执行耗时 |
| metadata | JSONB | 扩展信息 |

### 2.3 Span（执行单元：LLM 调用 / 工具调用 / 推理 / 检索 / 子任务）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | 主键 |
| span_id | String UNIQUE | Span 唯一标识 |
| trace_id | String FK | 所属 Trace |
| parent_span_id | String NULL | 父 Span（根为 null） |
| name | String | Span 名称 |
| span_type | String | 执行类型 |
| status | String | 执行状态 |
| started_at | DateTime | 开始时间 |
| ended_at | DateTime | 结束时间 |
| duration_ms | BigInt | 耗时 |
| input | JSONB | 输入 |
| output | JSONB | 输出 |
| error | JSONB | 错误信息 |
| metadata | JSONB | 扩展信息 |

### 2.4 TokenUsage（模型调用消耗）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | 主键 |
| trace_id | String FK | 所属 Trace |
| span_id | String FK | 所属 Span |
| model_name | String | 模型名 |
| prompt_tokens | Int | 输入 token |
| completion_tokens | Int | 输出 token |
| total_tokens | Int | 总 token |
| estimated_cost | Numeric | 估算成本 |
| currency | String | 币种 |
| created_at | DateTime | 时间 |

> 成本必须基于模型价格配置计算；价格未知时**标注为估算值**。

### 2.5 DiagnosticTask（诊断任务）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | 主键 |
| task_id | String UNIQUE | 任务标识 |
| project_id | UUID FK | 所属项目 |
| user_query | Text | 用户问题 |
| task_status | String | 状态 |
| execution_plan | JSONB | 执行计划 |
| diagnosis_result | JSONB | 诊断结果 |
| started_at | DateTime | 开始 |
| completed_at | DateTime | 完成 |
| error_message | Text | 错误信息 |

### 2.6 DiagnosticFinding（诊断发现）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | 主键 |
| finding_id | String | 发现标识 |
| task_id | String FK | 所属任务 |
| finding_type | String | 类型 |
| severity | String | 严重度 |
| title | String | 标题 |
| description | Text | 描述 |
| evidence | JSONB | 证据（可溯源到 Trace/Span） |
| confidence | Numeric | 可信度 |
| recommendations | JSONB | 建议 |

### 2.7 KnowledgeDocument（知识文档）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | 主键 |
| document_id | String UNIQUE | 文档标识 |
| title | String | 标题 |
| source | String | 来源 |
| content | Text | 原文 |
| document_type | String | 类型（md/txt/pdf/manual/report） |
| metadata | JSONB | 元信息 |
| created_at | DateTime | 时间 |

> Chunk 存 Qdrant，必须保留 `document_id` 与 `source` 以溯源。

### 2.8 MemoryRecord（长期记忆）
| 字段 | 类型 | 说明 |
|---|---|---|
| id | UUID PK | 主键 |
| memory_id | String UNIQUE | 记忆标识 |
| project_id | UUID FK | 所属项目 |
| memory_type | String | EPISODIC / SEMANTIC / PROCEDURAL |
| content | Text | 内容 |
| source_task_id | String | 来源任务 |
| metadata | JSONB | 元信息 |
| created_at / updated_at | DateTime | 时间 |

> 当前任务临时状态由 LangGraph State + Checkpointer 管理，**不重复写入 MemoryRecord**。

## 3. 索引设计

- `Trace(project_id, started_at)`：按项目+时间范围查询。
- `Trace(trace_id)` 唯一。
- `Span(trace_id)`：拉取完整 Span 树。
- `TokenUsage(trace_id)`、`TokenUsage(model_name, created_at)`：成本聚合。
- `DiagnosticTask(project_id, started_at)`。
- `DiagnosticFinding(task_id)`。
- `MemoryRecord(project_id, memory_type)`。

## 4. 迁移与演进

- 用 Alembic 管理，每个里程碑的 schema 变更写成独立 migration。
- JSONB 字段放灵活扩展信息；高频筛选字段独立成列并建索引。
- 不把诊断报告正文塞进单行 TEXT 过多——大文本可走 JSONB 或后续对象存储（第一阶段先存 PG）。
