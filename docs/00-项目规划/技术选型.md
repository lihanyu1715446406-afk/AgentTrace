## 2. 版本兼容性检查（2026-11-19 实测本机）

| 项 | 实测值 | 结论 |
|---|---|---|
| Python | 默认 3.14.3；**uv 已装 CPython 3.12.14** | ✅ 用 3.12.14 |
| uv | 0.12.13 | ✅ 用 uv 建 venv + 锁版本 |
| Docker | 29.9.2 | ✅ PG/Qdrant/Redis 走 compose |
| Node / npm | v24.15.0 / 11.12.1 | ✅ 前端 |
| Git | 2.55.0 | ✅ |
| DeepSeek | `DEEPSEEK_API_KEY` 已设置 | ✅ M1 直接接真实 LLM |

### 关键结论

1. **不用默认的 Python 3.14.3**：3.14 过新，部分二进制依赖（pydantic-core、asyncpg 等）wheel 覆盖可能存在滞后。项目锁定 **3.12.14**，规避风险。
2. **LLM = DeepSeek**：`deepseek-chat` 支持 OpenAI 兼容的 function calling（Tool Calling 依赖它）；`deepseek-reasoner` 不支持 function calling，Agent 场景一律用 `deepseek-chat`。
3. **DeepSeek 无 embeddings 接口**：RAG（M4）需另选 Embedding Provider，见 §4 待确认项。

## 3. 选型原则

1. 优先成熟稳定技术；
2. 避免重复引入功能相近框架（如不同时用 SQLAlchemy 和 Django ORM）；
3. 模型 / Embedding / 数据库访问必须抽象；
4. 不为堆技术栈而引入无用依赖。

## 4. 待确认 / 延迟项

| 项 | 状态 | 说明 |
|---|---|---|
| Embedding Provider | **M4 前定** | 候选：本地 BGE（sentence-transformers，免费但吃算力）/ SiliconFlow 等 OpenAI 兼容 embedding API / OpenAI。M1~M3 不涉及，暂缓 |
| Reranker | M4 第二阶段 | BGE Reranker（本地）或 API，可选 |
| Redis | M5 前接入 | 初期不引入，按里程碑接 |
| Qdrant | M4 接入 | 初期可用 PG + 本地文件起步 |

## 5. 依赖目录（目标大版本，M0 精确锁定）

- `langgraph`、`langchain`、`langchain-openai`（DeepSeek 走 OpenAI 兼容 base_url）
- `langchain-deepseek`（若可用则优先，否则用 `langchain-openai` + base_url）
- `fastapi`、`uvicorn[standard]`、`pydantic`、`pydantic-settings`
- `sqlalchemy`、`alembic`、`asyncpg` 或 `psycopg[binary]`
- `qdrant-client`（M4）、`redis`（M5）
- `pytest`、`pytest-asyncio`、`httpx`
- 前端由 `frontend/` 的 npm 管理，不并入 Python 依赖
